# 异常测试记录（实验3 桌面物体自动分类整理）

> 验收要求（《实验3 桌面物体自动分类整理实验要求》）：
> - **§三**：循环处理桌面上的物体，直至全部处理完成或没有可执行目标；处理**空网格、未识别物体、
>   不可达目标和抓取失败**等异常。
> - **§四（仿真验收）**：**至少正确处理 2 类异常**，并保存**识别、抓取和任务状态日志**。
> - **§五（真机）**：空网格和未识别物体应被跳过；抓取失败或目标不可达时应返回安全位置或停止。
>
> 被测实现 = `sort_core/task.py` 的 `TaskController` 状态机（离线可测）＋ 两条线各自的
> “阶段失败 → reason”映射：**仿真线**是 `ros2/task_control/pick_place_server.py`（+ `c4_executor.py`），
> **真机线**是 `real/ep_backend.py`（`EPPickPlace._fail`）。
> 异常分两层处理：**任务级**由控制器判定（跳过 / 退出），**动作级**由 `reason` 给出。
> 离线等价触发见 `examples/run_demo.py --mode <场景>`（仿真线）与
> `real/run_real.py --dry-run`（真机线，mock 检测器 + 假 EP），
> 日志分别落 `exp3_logs/run_<时间戳>/` 与 `exp3_logs_real/run_<时间戳>/`。
>
> 两层的 reason 枚举与阶段号**两条线完全一致**（同一份 `sort_core/taxonomy.py`、同一个
> `PickExecutor` ABC），所以本文件的结论对两条线同时成立 —— 差别只在“谁把段号映射成 reason”
> （server 的 `_FAIL_IF_STAGE_FAILS` vs 执行器的 `STAGE_REASON`）。

## 1. 任务级异常（控制器判定；离线 demo 实测）

“如何触发”列即 `examples/run_demo.py --mode <…>` 的场景名，可原样复跑核对。

| 编号 | 异常类型 | 触发方式 | 预期行为 | 实现对照（`sort_core/task.py`） | 实测结果 | 通过 |
|:---:|---|---|---|---|---|:---:|
| 1 | 空网格 / 桌面清空 | `happy`（6 物处理完后再扫为空） | 正常结束，不误报失败 | `dets == []` → `exit_status = no_target`，break | verdict=**PASS** `placed_ok=6` `exit=no_target` | ✅ |
| 2 | 未识别物体 | `unrecognized`（6 格全为未知类 `stapler`） | 逐条跳过**且只记一条**，空转达上限后结束 | `classify` 未知类/低置信 → `unrecognized_object`；`logged_skip` 按 (cell,cls) 去重；空转 ≥ `no_exec_limit` → `no_exec` | verdict=FAIL `reasons={unrecognized_object:6, no_exec:1}` `exit=no_exec` | ✅ |
| 3 | 目标不在网格 | `out_of_grid`（框中心落在网格外、仍在画面内） | 跳过，不尝试抓取 | `locate` 命中不到 cell → `out_of_grid` 跳过 | verdict=TRIAL `reasons={out_of_grid:1, no_exec:1}` `exit=no_exec` | ✅ |
| 4 | 抓取失败（可恢复） | `recovery`（每物先失败 1 次再成功） | 单次失败**不终止**，重扫重试；偶发失败不应拖垮整轮 | `pick_place≠ok` → `fail_streak+=1`、重扫；成功即 `fail_streak=0` | verdict=**PASS** `placed_ok=6` `reasons={grasp_failed:6}` | ✅ |
| 5 | 连续抓取失败 → 安全停止 | `safety_stop`（同一物连续失败） | 连续失败达 `fail_limit` 后**保护性停止**，记录原因并调 `safe_stop` | `fail_streak >= fail_limit` → `exit_status=safety_stop`，`safe_stop(REASON_SAFETY_STOP)` | verdict=TRIAL `reasons={grasp_failed:3, safety_stop:1}` `exit=safety_stop` | ✅ |
| 6 | 只剩不可执行目标 | 由 #2/#3 的空转分支覆盖 | 空转次数达 `no_exec_limit` 即退出，不空转死循环 | `no_exec_streak >= no_exec_limit` → `no_exec` | 同 #2/#3（`no_exec` 计入 reasons） | ✅ |

> **“≥2 类异常正确处理”对照**：上表 #2（未识别物体）、#3（不在网格）、#5（连续失败安全停止）
> 均已在离线 e2e 中触发并留日志 —— 满足 §四 的“至少 2 类”。

## 2. 动作级异常（`PickPlace` result.reason；两条线各自的映射 + 单测）

一次取放的失败原因只出动作级枚举（`sort_core/taxonomy.py`）；映射方按**失败发生的阶段**
决定具体 reason —— 仿真线是 `pick_place_server.py` 的 `_FAIL_IF_STAGE_FAILS`，
真机线是 `real/ep_backend.py` 的 `STAGE_REASON`。两条线的表**逐项一致**：

| reason | 含义 | 触发阶段 | 阶段 → reason | 验证 |
|---|---|---|---|:---:|
| `unreachable_target` | 不可达 / 逆解失败 / 路径规划失败 | 下探、搬运 | 两线一致：`STAGE_APPROACH` / `STAGE_MOVE_TO_BIN` 失败 | ✅ 单测（两线） |
| `grasp_failed` | 抬离后判未夹起 | 抬离 | 两线一致：`STAGE_LIFT` 失败（判 held 不过） | ✅ 单测（两线） |
| `dropped_or_missed_place` | 松放后判掉件 / 放偏 | 松放 | 两线一致：`STAGE_PLACE` 失败（判 placed 不过） | ✅ 单测（两线） |
| `exec_error` | ROS / 驱动硬错（含异常抛出） | 任意段抛异常 | 两线一致：`except Exception` 兜底 | ✅ 单测（两线） |
| `aborted` | 被取消 / 中断 | 任意（`is_cancel_requested`） | 收到取消 → `aborted` | ✅ 单测 |
| `exec_error` | **夹取段失败** | 夹取（压紧） | ✅ 两线一致（`exec_error`） | ✅ 单测（两线） |
| `unreachable_target` / `exec_error` | **退回段失败** | 退回 | ⚠ **两线不同**：仿真 `unreachable_target`／真机 `exec_error` | ✅ 单测（两线） |

> **两条线只在 RETRACT 一段上映射不同，且是故意不同**（其余五段逐项一致）——
> 写在这里是为了**以后有人比对两线日志时不会以为其中一份写错了**：
>
> 真机 `STAGE_REASON` 的总规则是：**只报这一段的代码真能做出来的判断，
> 不替谁宣布一个没人做过的判定。**（EP 上每一段都只能靠异常失败——只有 `lift`/`release`
> 会返回 `False`，所以那张表实际上是“按段解释那次异常”。）
>
> | 段 | 仿真线 `_FAIL_IF_STAGE_FAILS` | 真机线 `STAGE_REASON` | 说明 |
> |---|---|---|---|
> | `STAGE_GRASP`(2) | `exec_error` | `exec_error` | 两线一致：夹爪闭合**动作本身**失败属硬错。 |
> | `STAGE_RETRACT`(6) | `unreachable_target` | `exec_error` | 仿真那个 reason 来自**规划器的可达性判定**；EP **没有规划层**，没有任何东西产出过“不可达”这个结论 ⇒ 报驱动硬错（`exec_error`）才是如实描述。 |
>
> 这一处不同**不影响任务级行为** —— `TaskController` 只区分 ok / 非 ok，非 ok 一律累加
> `fail_streak`，所以 retry 与 safety_stop 的走向完全相同，差别只在 `result.json` 的
> `reasons` 直方图怎么归类。
>
> 📌 **`STAGE_GRASP` 曾填 `grasp_failed`，2026-09-16 已改成 `exec_error`**（连同单测
> `tests/test_ep_backend.py::test_gripper_close_fail_exec_error`）。原口径偏松：`grasp_failed`
> 在 taxonomy 里的定义是“**抬离后判定没夹起**”，可真机 `grasp()` 只调 `rm.gripper_close()`，
> **从没判过 held**（判 held 在下一段 `lift()`）—— 填它等于**凭空宣布一个没做过的判定**。
> 现在两线在夹取段口径一致，`grasp_failed` 只由 `STAGE_LIFT` 产出。

客户端（`pick_place_client.py`）对非动作级返回值兜底成 `exec_error`，保证控制器断言
（`res in ACTION_REASONS`）不被越界值打破。

**真机线特有的收尾语义**（`EPPickExecutor`，仿真线无此项）：EP 是**开环**的，某一段失败后
机械臂停在哪里没有反馈 ⇒ 每个失败都立刻 `safe_reset`（开爪 → 抬到高 → 回 HOME），
否则下一轮等于拖着臂横扫桌面。单测 `tests/test_ep_backend.py::TestFailureMapping`
的 `test_every_failure_ends_in_safe_reset` 逐段注入失败，断言**每一段失败后都调了收尾**。

## 4. 安全停止 / 跳过 / 退出 语义汇总

| 情形 | 行为 | 落盘 |
|---|---|---|
| 空网格 / 桌面清空 | 正常结束（**不是**失败） | `exit_status=no_target` |
| 未识别物体 / 不在网格 | 跳过该目标，**只记一条**；不尝试抓取 | `decision=skip` + `skip_reason` |
| 持续只剩不可执行目标 | 空转达上限后结束 | `exit_status=no_exec` |
| 单次抓取失败 | 不终止，重扫重试 | `decision=exec` + 动作级 `reason` |
| **连续**失败达 `fail_limit` | **保护性停止**，调用 `safe_stop` | `exit_status=safety_stop` |
| 被取消 / 中断 | 按 `aborted` 收尾 | `result.reason=aborted` |

> 语义分层原则：**“偶发抖动”与“真卡死”必须能区分** —— 单次失败只累计计数、继续跑；
> 只有**连续**失败才停机，避免一次误检就让整轮验收中断。

## 5. 复现命令（离线，无需 ROS / 真机）

```bash
cd exp3
python3 -m unittest discover -s tests -t . -v      # 205 个离线用例（含上述异常路径）

# 仿真线：任务级异常逐个复跑
python3 examples/run_demo.py --mode safety_stop    # 连续失败 → safety_stop
python3 examples/run_demo.py --mode unrecognized   # 未识别物体 → no_exec
python3 examples/run_demo.py --mode out_of_grid    # 不在网格 → no_exec
python3 examples/run_demo.py --mode recovery       # 抓取失败可恢复 → PASS
# 日志：exp3_logs/run_<时间戳>/{run.log, records.jsonl, result.json}

# 真机线：同一套异常，用 mock 检测器注入 + 假 EP 复跑（不连硬件）
python3 real/run_real.py --config-dir config_real --dry-run --camera none \
        --detector mock --assume-judge --no-pause
python3 real/run_real.py --config-dir config_real --dry-run --camera none \
        --detector mock --scene <注入异常的 scene.json> --assume-judge --no-pause
# 日志：exp3_logs_real/run_<时间戳>/（同样的 records.jsonl + result.json schema）
```

真机线四类异常的**离线注入方式与断言**（`tests/test_run_real.py::TestAbnormal`，
在真机上没法反复试，所以先在这里钉死）：

| 异常 | 注入方式 | 断言 |
|---|---|---|
| 未识别物体 | scene 的 `extra_dets` 加一条未知类 | `placed_ok=6`、`reasons[unrecognized_object]=1`、`exit=no_exec` |
| 置信度不足 | `extra_dets` 加一条 `conf=0.3`（< `conf_min=0.5`） | 同上（走 `unrecognized_object`，不是“看不见”） |
| 目标不在网格 | `extra_dets` 加一条落在网格外的框 | `reasons[out_of_grid]=1`、其余 6 个照常分类 |
| 抓取失败 → 安全停止 | HELD 一律答 no（操作员一直说没夹住） | 连续 3 次 `grasp_failed` → `exit=safety_stop`；<br>共问 6 次 HELD（3 轮 × 首次+重抓），**不许无限重试** |

# 异常测试记录（实验3 桌面物体自动分类整理）

> 验收要求（《实验3 桌面物体自动分类整理实验要求》）：
> - **§三**：循环处理桌面上的物体，直至全部处理完成或没有可执行目标；处理**空网格、未识别物体、
>   不可达目标和抓取失败**等异常。
> - **§四（仿真验收）**：**至少正确处理 2 类异常**，并保存**识别、抓取和任务状态日志**。
> - **§五（真机）**：空网格和未识别物体应被跳过；抓取失败或目标不可达时应返回安全位置或停止。
>
> 被测实现 = `sort_core/task.py` 的 `TaskController` 状态机（离线可测）＋
> `ros2/task_control/pick_place_server.py` 的“阶段失败 → reason”映射。
> 异常分两层处理：**任务级**由控制器判定（跳过 / 退出），**动作级**由 Action 的
> `result.reason` 给出。离线等价触发见 `examples/run_demo.py --mode <场景>`（mock 后端），
> 日志落 `exp3_logs/run_<时间戳>/`（`records.jsonl` + `run.log` + `result.json`）。

## 1. 任务级异常（控制器判定；离线 demo 实测）

“如何触发”列即 `examples/run_demo.py --mode <…>` 的场景名，可原样复跑核对。

| 编号 | 异常类型 | 触发方式 | 预期行为 | 实现对照（`sort_core/task.py`） | 实测结果 | 通过 |
|:---:|---|---|---|---|---|:---:|
| 1 | 空网格 / 桌面清空 | `happy`（6 物处理完后再扫为空） | 正常结束，不误报失败 | `dets == []` → `exit_status = no_target`，break | verdict=**PASS** `placed_ok=6` `exit=no_target` | ✅ |
| 2 | 未识别物体 | `unrecognized`（6 格全为未知类 `stapler`） | 逐条跳过**且只记一条**，空转达上限后结束 | `classify` 未知类/低置信 → `unrecognized_object`；`logged_skip` 按 (cell,cls) 去重；空转 ≥ `no_exec_limit` → `no_exec` | verdict=FAIL `reasons={unrecognized_object:6, no_exec:1}` `exit=no_exec` | ✅ |
| 3 | 目标不在网格 | `out_of_grid`（框中心落在网格外、仍在画面内） | 跳过，不尝试抓取 | `locate` 命中不到 cell → `out_of_grid` 跳过 | verdict=TRIAL `reasons={out_of_grid:1, no_exec:1}` `exit=no_exec` | ✅ |
| 4 | 抓取失败（可恢复） | `recovery`（每物先失败 1 次再成功） | 单次失败**不终止**，重扫重试；偶发失败不应拖垮整轮 | `pick_place≠ok` → `fail_streak+=1`、重扫；成功即 `fail_streak=0` | verdict=**PASS** `placed_ok=6` `reasons={grasp_failed:6}` | ✅ |
| 5 | 连续抓取失败 → 安全停止 | `safety_stop`（同一物连续失败） | 连续失败达 `fail_limit` 后**保护性停止**，记录原因并调 `safe_stop` | `fail_streak >= fail_limit` → `exit_status=safety_stop`，`safe_stop(REASON_SAFETY_STOP)` | verdict=TRIAL `reasons={grasp_failed:3, safety_stop:1}` `exit=safety_stop` | ✅ |
| 6 | 只剩不可执行目标 | 由 #2/#3 的空转分支覆盖 | 空转次数达 `no_exec_limit` 即退出，不空转死循环 | `no_exec_streak >= no_exec_limit` → `no_exec` | 同 #2/#3（`no_exec` 计入 reasons） | ✅ |

> **“≥2 类异常正确处理”对照**：上表 #2（未识别物体）、#3（不在网格）、#5（连续失败安全停止）
> 均已在离线 e2e 中触发并留日志 —— 满足 §四 的“至少 2 类”。

## 2. 动作级异常（`PickPlace` result.reason；server 映射 + 单测）

一次取放的失败原因只出动作级枚举（`sort_core/taxonomy.py`）；`pick_place_server.py` 按
**失败发生的阶段**决定具体 reason（见其 `_FAIL_IF_STAGE_FAILS`）。

| reason | 含义 | 触发阶段 | server 映射（阶段 → reason） | 验证 |
|---|---|---|---|:---:|
| `unreachable_target` | 不可达 / 逆解失败 / 路径规划失败 | 下探、搬运、退回 | `STAGE_APPROACH` / `MOVE_TO_BIN` / `RETRACT` 失败 | ✅ 单测 |
| `exec_error` | ROS / 规划 / 驱动硬错（含异常抛出） | 夹取；或任意段抛异常 | `STAGE_GRASP` 失败；`except Exception` 兜底 | ✅ 单测 |
| `grasp_failed` | 抬离后判未夹起 | 抬离 | `STAGE_LIFT` 失败（判 held 不过） | ✅ 单测 |
| `dropped_or_missed_place` | 松放后判掉件 / 放偏 | 松放 | `STAGE_PLACE` 失败（判 placed 不过） | ✅ 单测 |
| `aborted` | 被取消 / 中断 | 任意（`is_cancel_requested`） | 收到取消 → `aborted` | ✅ 单测 |

客户端（`pick_place_client.py`）对非动作级返回值兜底成 `exec_error`，保证控制器断言
（`res in ACTION_REASONS`）不被越界值打破。

## 4. 安全停止 / 跳过 / 退出 语义汇总

| 情形 | 行为 | 落盘 |
|---|---|---|
| 空网格 / 桌面清空 | 正常结束（**不是**失败） | `exit_status=no_target` |
| 未识别物体 / 不在网格 | 跳过该目标，**只记一条**；不尝试抓取 | `decision=skip` + `skip_reason` |
| 持续只剩不可执行目标 | 空转达上限后结束 | `exit_status=no_exec` |
| 单次抓取失败 | 不终止，重扫重试 | `decision=exec` + 动作级 `reason` |
| **连续**失败达 `fail_limit` | **保护性停止**，调用 `safe_stop` | `exit_status=safety_stop` |
| 被取消 / 中断 | 按 `aborted` 收尾 | `result.reason=aborted` |

> 语义分层原则：**“偶发抖动”与“真卡死”必须能区分** —— 单次失败只累计计数、继续跑；
> 只有**连续**失败才停机，避免一次误检就让整轮验收中断。

## 5. 复现命令（离线，无需 ROS / 真机）

```bash
cd exp3
python3 -m unittest discover -s tests -t . -v      # 47 个离线用例（含上述异常路径）
python3 examples/run_demo.py --mode safety_stop    # 连续失败 → safety_stop
python3 examples/run_demo.py --mode unrecognized   # 未识别物体 → no_exec
python3 examples/run_demo.py --mode out_of_grid    # 不在网格 → no_exec
python3 examples/run_demo.py --mode recovery       # 抓取失败可恢复 → PASS
# 日志：exp3_logs/run_<时间戳>/{run.log, records.jsonl, result.json}
```

# 实验3 真机标定说明（EP 线，持机人必读）

> 目标：把 `config_real/` 里**四份**标定记录填全，让 `run_real.py` 能跑完整任务（6 个物体 → 2 个料盒）。
> **每换场地 / 每次重新上电都要重标底盘位姿**（odom 原点跟着上电位姿走）；臂两档与夹爪档位一次标好后可复用。
> 全程先小动作、人盯，别一上来就跑整轮。
>
> 工具：`real/calibrate.py` —— **读数直接写回表，不用手抄**（手抄 9×3 个数，抄错一个就是一个撞桌的点位）。
> 本文只讲 EP 那一份；相机/网格/料盒三份在 §4 一句话交代，各自的做法写在自己 config 的 `calibration.note` 里。

## 0. 前置：确认"工程形态" + 装 SDK

- EP 必须是**工程形态**（底盘上方是 2 轴机械臂 + 机械夹爪，没有云台）。步兵形态没有 arm/gripper
  模块，连上也会立刻报错。
- 官方 RoboMaster SDK：DJI 开发者站下载，或
  `git clone https://github.com/dji-sdk/RoboMaster-SDK && cd RoboMaster-SDK && python setup.py install`
  （建议 Python 3.8/3.9）。装完 `python3 -c "import robomaster"` 不报错即可。
- EP 上电；`ep/config_ep.json` 里 `robot.conn_type` 默认 `ap`（电脑连 EP 热点）；若电脑要同时上网就改 `sta`。
- 先看进度、知道还差什么：

  ```bash
  python3 real/calibrate.py                  # 列出哪些位姿/档位还没标
  ```

  > 连不上机器人时它不会甩 traceback，会打三条排查提示（SDK / 热点 / 工程形态）。

## 1. 九组底盘位姿 —— 每场地必标

原理：EP 靠**里程计**定位，读数从**上次上电**那一刻的位置开始累计（`chassis.odom_cs=1`）。
把 EP 摆到"爪中轴对准该格中心、爪底略高于物体顶面"的位姿，抄下 odom `(x_m, y_m, z_deg)` 记进表。

**为什么格子之间要动车**：EP 臂只有**一个水平自由度**（前伸 `x_mm`）。桌面的横向覆盖只能靠
底盘横移/转向过去 —— 所以每一格是一个**底盘位姿**，`goto()` 把车开过去再由臂下探。

读法（两个命令，一条都别少）：

```bash
python3 real/calibrate.py --odom                # 实时刷 odom（推着车到位，Ctrl-C 停）
python3 real/calibrate.py --record c1           # 车已在位 → 把这组读数记进 c1
```

`--record` 接受：`c1`…`c6`（网格）、`bin_cup` / `bin_mouse`（料盒）、`home_pose`（归位点，写
`home` 也一样）。**已经有值时它会拒绝覆盖**，确认要改加 `--force`。

操作顺序：

1. **格子 c1…c6**：把目标物放到该格 → 车开到"爪中轴对准中心、爪底略高于顶面"→ `--odom` 读数 →
   `--record cN`。6 格逐个走完。
2. **料盒 bin_cup / bin_mouse**：料盒摆到**网格外侧**（docx §五 要求分类区域 ≥ 2 个）→ 同样读数记录。
   摆之前先确认：**从该位姿下探不会压到网格、也不会撞桌沿**。
3. **home_pose**：挑一个离所有格子和料盒都安全、不碍事的角落（每轮结束回这里，既把误差"重零"
   一部分，也方便你人工补物）。
4. 上面 9 组数**必须在同一次开机里读完**才是一套 —— 中途重启过就重读，并把 `calibration.note`
   写清是"哪次开机的原点"。

> **换场地 / 重新上电 ⇒ 全部作废**。用 `--invalidate` 把 `status` 打回 `uncalibrated`；
> 它同时会告诉你**哪些不用重标**（臂两档和夹爪档位在臂坐标系里，跟车停在哪无关）。
> 直接改 `status` 而不重标，等于让车照着错的原点开出去 —— 闸门拦不住这种，只能靠这条纪律。

> 若某格与另一格之间转了朝向（不只是平移），`z`（deg）会不同，照实记；纯平移通常 `z` 一致。

## 2. 臂两档 grab_low / lift_high —— 一次标好

臂末端位姿是 **2 元列表 `[x_mm, y_mm]`**（x = 前伸，y = 高度，**y 增大 = 向上**，
由实验二 2026-09-13 的 5mm 实测坐实）。

| 档 | 含义 | 判据 |
|---|---|---|
| `grab_low_mm` | 下探到夹持高度 | 爪指**正好包住**物体的夹持部位，能闭爪夹住 |
| `lift_high_mm` | 悬停高度 | 爪底**高于物体顶面**（移车/放物都刮不到） |
| `release_low_mm` | 释放高度 | **`null` 是合法值** = 与 `grab_low_mm` 同高；料盒有沿/垫高才单独标 |

标法：

```bash
python3 real/calibrate.py --record-arm grab 74 120     # 移到 (74,120)，人眼看爪到哪
```

它会：移到目标 → 等读数稳定 → 打印「要求 (…) → 读回 (…)，差 x.x mm」→ 问你**爪的位置对不对** →
你确认后写进表。对不上就换个目标再试，**不写表**。

> ### ★ 钳制陷阱（这一节是本文档最重要的一条）
> **越界的命令会被 SDK 安静地钳制**，臂"稳定地停在"一个并非目标的读数上，而且 SDK 只打一条
> WARN、**从不抛异常**。于是现象看起来是"抓取不稳定"，实际是这一档**永远够不到**。
> 所以 `--record-arm` 会核对读回值：**差超过 `ARM_MISS_TOL_MM`（3.0mm）就拒绝记录**，
> 除非你明确加 `--force`。
> 判断"是不是被钳制了"看两个 WARN：`arm 读数 6s 内未稳定（行程被钳制?）` 或
> `arm 未到位 —— 要求 (…) 读回 (…)`。看到就改小重试，别照抄。
>
> 读回值**已经等推送追上再打印**（`ep/drive/rm.py` 的 `_settle_arm`）：SDK 的 `action_succeeded`
> 比位置推送早约 0.5s（实测：指令 47ms 报完成，位置推送到 0.56s 后才出现新值），紧跟动作完成
> 就读会打印**动作前的旧位姿**。位置读数走**订阅**（SDK 没有 `arm.get_position()`）。
> 离线复现这三个场景：`python3 ep/tools/test_arm_settle_offline.py`。

容差按 **±2mm** 看（实测稳态 ±1mm 抖动，x 有 +1mm 固定偏移 74→75）。
**别照抄 0** —— 实验二实测校准后 x 在几十 mm 量级（x≈74）。

**臂能不能下探够到物体的抓握高度，是选型前必须现场验的事。**
官方标称**垂直行程 ~0.15m**，但那只是行程范围，**不是 SDK 里 y 坐标的上限**。

**实测到哪一步，说清楚（2026-09-14 C5 跑，`docs/真机侧证据_EP_20260914/ep_c5_run_20260914_231815.log`）**：

| | 值 |
|---|---|
| 命令到过的负 y | **−22 mm**（`A_grab_low`，5 次）、**−24 mm**（`B_release_low`，5 次） |
| **读回**到过的最低 y | **−20 mm**（全日志 100+ 条读回里再没有更低的） |
| 读回与命令的差 | 普遍 **2~8 mm**，且**不总是偏低**（`travel_safe` 命令 y=41，读回恒为 42，是**偏高**） |

⇒ 结论只能说到这一步：**控制器敢下探到 −22/−24，但没有任何一条读回证实臂真的到过 −20 以下。**
至于 −20 是不是硬下限，**这份日志证明不了** —— 读回整体带 2~8mm 的偏差/滞后，
"撞限位"和"读数有固定偏移"两种解释它分不开。**现场必须自己 jog 出真实下限**
（`python3 real/calibrate.py --record-arm`，它按 3mm 容差**拒绝**存下被钳制的值）。

另：那次夹的是**直立的**矿泉水瓶（日志第 10 行「瓶子直立放在 A 框内部定位标记」），
抓握面在瓶身中段；而实验三若用矮的 cup 或**扁平的 mouse**（要在 **1~2cm** 高度处夹），
够不够得到**没人验过**。现场先试，够不到就垫高。
> ⚠ 离线假 SDK（`ep/tools/test_arm_settle_offline.py:63`）按 `min(max(y,0),150)` 建模钳制，
> **与真机相反**，别拿它当依据。

## 3. 夹爪 open / close power（1..100）

从 60 起步。先试夹、记档：

```bash
python3 real/calibrate.py --grip close --power 60      # 按这档合一次夹爪（不写表）
python3 real/calibrate.py --record-grip close 60       # 试好了再记
```

- 看两件事：**夹稳不掉** + **电机不啸叫**（夹爪带力度控制，不用拉满；咯吱响/憋电机就降）。
- 关键验证（**运送不松爪**）：跑起来后盯"闭爪到放料盒的一路上有没有松"。松就加 `close_power`。
- **mouse 是扁平件，是这两个类里最容易掉/最难夹的** —— 它的档位要单独试，别沿用同一次的值。
  圆瓶身/薄壁杯壁滑，同一 power 下更容易转/滑脱。
- `_check_power` 会拦越界值（非整数、或不在 1..100）。

## 4. 另外三份标定记录（不是本文重点，但闸门一起查）

四份记录**分开署名**，就是为了出问题时知道**卡在谁那里**：

| 记录 | 谁 | 做法（详见各自 config 的 `calibration.note`） |
|---|---|---|
| `task.json` → `camera.calibration` | **乙** | 桌上摆 4 个已知点（卷尺量）→ 图里读像素 → 解 H（DLT）。判据：反投影误差 ≤ 半个格子宽 |
| `grid_cells.json` → `calibration` | 组长/甲 | 胶带贴 2×3 格，卷尺量每格两角 → 回填 `x0/y0/x1/y1` |
| `bins.json` → `calibration` | 组长 | 料盒中心坐标回填 `x_m/y_m`（先确认够得到、不压网格） |

**相机的 `mode` 必须是 `homography`，不是 `rectilinear`** —— 我们**没有相机支架**，相机是
垫高放桌上斜俯视的，`rectilinear` 只在光轴垂直向下时成立。改分辨率会改变像素尺度，旧标定直接作废。

## 5. 封表 + 过全闸门

本表填全 → 封表（写 `by`/`date`/`venue` + `status=calibrated`）：

```bash
python3 real/calibrate.py --seal --by 马晨曦 --venue 实验室
```

填不全它会**拒绝封表**并列出还差哪几项。然后过**四份记录一起查**的全闸门：

```bash
python3 config_check.py --config-dir config_real --require-calibrated
```

归零之后才谈得上开跑。`run_real.py` 启动第一件事就是过这道闸，**没过连机器人都不连**。

> 闸门为什么必须前置：实验二的教训是 config 里编的占位值照样通过全部结构检查（A/B 相距 0.6m
> > 0.1m 阈值，恰好过），"是否已标定"这条检查从来没起过作用。真机拿没标定的点位跑，轻则空抓
> 重则撞桌。所以这里做成硬门，**不在同一个进程里给"跳过闸门"的选项** —— 要跳过只能去改 config
> 里的标定记录，那是留痕的。没解锁就被拒绝是**正常设计，不是 bug**。

## 6. 首跑纪律（和 c4_2 / 实验二真机同一套）

1. **先演练动作链**（不碰真机、不需要标定过闸门 —— 注意会被闸门拦，这是设计）：

   ```bash
   python3 -m unittest tests.test_run_real tests.test_ep_backend -v   # 看链路，不碰硬件
   ```

2. **第一轮真机跑开 `--confirm-each`**：每个物体动手**之前**等一次回车，全程人盯。

   ```bash
   python3 real/run_real.py --config-dir config_real --confirm-each
   ```

   它是"人工触发动作"（docx §六 禁的那件事），所以这一轮**只能当演练** —— 见 §8。
3. 确认一个完整轮次 OK，再**关掉 `--confirm-each`** 跑记分轮（6 个物体 → 5 个以上入对盒）。
4. 结果在 `exp3_logs_real/run_*/result.json`；"这次是怎么跑出来的"在同一个目录的 `real_run.json`。
5. **连不上 EP 不算"跑了失败"**：`--confirm-each` 之外还有一个更早的分叉 —— 连都没连上时，
   照样留一份 `result.json`（`placed_ok=0`、`exit_status=no_exec`），并在 `real_run.json` 里记
   `outcome=connect_failed` 与错误原文。否则目录里只有 `run.log`、没有 `result.json`，
   "没连上"和"跑挂了"从文件上分不出来。

## 7. 掉点排查速查

| 现象 | 优先检查 |
|---|---|
| 到某格每次偏 | 重标底盘位姿；该格与相邻格的 `z` 是否记错；`--invalidate` 过没有（换场/重上电后） |
| 爪对不准物体 | `grab_low_mm` 的 x，或该格底盘位姿的朝向 `z` |
| 夹不稳 / 运送掉 | `close_power` 太低；目标物是 mouse（扁平）时尤其；料盒面不平 |
| 臂"抓不到"但读数很稳 | **钳制**（§2）：看有没有 `arm 未到位` WARN，读回值差多少 |
| 放下偏 / 翻 | `bin_pose` 未标准；释放太低爪刮到物体（释放前先抬一点） |
| 物体在网格里"不见了" | 检测侧（相机标定 / conf_min），不是 EP 侧 |
| arm 不动 / 报错 | 非工程形态？SDK 版本？属性名没探测到？ |
| 一启动就退出、没连机器人 | 标定闸门没过 —— 看它点名的是哪份记录（§5） |

## 8. 三个开关会让本次运行不算验收凭据

docx §六 要求"正常任务过程中不进行人工类别判断和动作触发"。三个开关分别违背其中一条：

| 开关 | 意味着 | 本次运行 |
|---|---|---|
| `--dry-run` | 没碰真机（用假 EP 打动作链） | rehearsal |
| `--assume-judge` | 没人确认夹住/放正（一律算成功） | rehearsal |
| `--confirm-each` | 人按回车才动作（人工触发动作） | rehearsal |

它们在 `real_run.json` 里被算成 `evidence_grade`（`acceptance` / `rehearsal`）并记下
`rehearsal_reasons`。**与其靠人记，不如算出来写进文件** —— 验收时一查就知道这一份能不能用。

> 例外说明：HELD/PLACED **两处人工 y/n 不算**违背 §六。EP 没有任何物块位姿感知，判"夹住没有/
> 放正没有"只能人来；§六 禁的是**判类别**（类别由识别给）和**触发动作**（动作由任务控制给）。
> 正常的验收跑 `operator_confirms = 2×物体数`，这个数也记在 `real_run.json` 里，可查。

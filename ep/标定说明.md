# EP 真机标定说明(持机人必读)

> 目标: 把 `config_ep.json` 里三类"真机数值"标出来, 让 `ep_cycle.py` 能稳定做 5 次取放。
> **每换场地/每次开机建议重标底盘坐标**(里程计原点/漂移会变); 臂坐标与夹爪档位一次标好后基本复用。
> 标定全程先 `--jog`/`--grip` 慢速小动、人盯, 别一上来就跑 5 周期。

> **⚠ 标定闸门(2026-09-13 加)**: `config_ep.json` 里底盘三组坐标出厂是 `null`,
> `calibration.status` 是 `"uncalibrated"`。**这种状态下 `ep_cycle.py` 直接拒绝启动、不会连机器人**;
> `env_check.py` 仍可跑(它本身就是标定工具)。按 §1–§3 标完、把 `status` 改成 `"calibrated"`
> 并填上 `by`/`date`/`venue` 之后, 才放行。
> 加这个是因为: 原先的示例占位值([0.35,0,0]/[0.35,0.6,0])**能通过全部离线校验** ——
> "检查是否还没标定"那条本来就查不出来, 一旦有人图快直接跑, 底盘会照着编出来的坐标开出去。

## 目标物口径(先读这一条, 2026-09-14 更正)

| | 目标物 | 放置面 |
|---|---|---|
| **真机(RoboMaster EP)——实际执行** | **矿泉水瓶(约 550mL 塑料瓶)** | **地面**(胶带贴出 A/B 框) |
| 仿真(mechArm 270 + Gazebo) | 5cm 立方体(≤100g) | 桌面/垫高面 |

两侧不同是**真实差异, 不是文档笔误**: 真机平台 2026-09-08 由 mechArm 换成 EP 后, 现场实际
夹的是水瓶。证据: `docs/真机侧证据_EP_20260914/ep_grasp_demo_20260914.mp4`(夹取→带物转移→
到位释放, 六帧抽检全程只有水瓶)。

**对本文档的实际影响**: §2 的两档臂坐标与 §3 的夹爪 power **原先都是按方块给的**, 换成瓶子
必须**重标** ——

- 瓶身比方块高得多、抓握面高 → `grab_low` 的 **y(高度)** 与 **x(前后)** 都要重试;
  视频里 EP 在地面就能夹到瓶子, 就是因为瓶子把抓握面抬高了; 换回 5cm 方块放地面则够不到。
- 瓶身是**圆的且比方块滑** → 同一 power 下更容易转/滑脱, §3 的 60 只是起点。
- 瓶子会被**碰倒/滚走** → B 落点"放偏/翻"的判据比方块更严。

换目标物就重走 §2–§3, 别沿用旧值。验收口径(5 次连续 ≥4 成功、人工 HELD/PLACED 确认)
**不受影响**, 变的是标定值。

## 0. 前置: 确认"工程形态" + 装 SDK

- EP 必须装成**工程形态**(底盘上方是 **2 轴机械臂 + 机械夹爪**, 没有云台)。步兵形态没有
  arm/gripper 模块, `env_check` 会直接报错。
- 电脑装官方 RoboMaster SDK: DJI 开发者站下载, 或
  `git clone https://github.com/dji-sdk/RoboMaster-SDK && cd RoboMaster-SDK && python setup.py install`
  (建议 Python 3.8/3.9)。装完 `python -c "import robomaster"` 不报错即可。
- EP 上电开机; `config_ep.json` 里 `robot.conn_type` 默认 `ap`(电脑连 EP 的热点); 若电脑要
  上网联调就改 `sta`(EP 与电脑都连同一路由器)。

## 1. 底盘三组坐标(HOME / A / B)—— 每场地必标

原理: EP 靠里程计定位, 读数从开机/上电后累计。把 EP 开到"爪子正好在标记点正上方"的位姿,
记下当时 odom `(x, y, z_deg)` 填进 config。

拿读数**只有一条路: 订阅**(2026-09-13 对着官方 0.1.1.68 源码坐实 —— SDK 里
`chassis.get_position()` **不存在**, 只有 `chassis.sub_position(freq, callback)`)。
已经封好在 driver 里, 现场直接用:
```bash
python3 ep/drive/env_check.py --config ep/config_ep.json --odom   # 把车摆到位, 0.5s 刷一次, 抄数
```
> 别去写 `ep.chassis.get_position()` —— 会 AttributeError。若确实要用裸 SDK 读一次:
> ```python
> import time
> from robomaster import robot
> ep = robot.Robot(); ep.initialize(conn_type='ap')
> got = []
> ep.chassis.sub_position(cs=1, freq=5, callback=lambda v, *a: got.append(v))   # cs=1: 上电原点
> time.sleep(0.5)                       # 等推送上来 —— 没有同步 getter, 必须等
> print('odom =', got[-1])              # (x_m, y_m, z_deg)
> ep.chassis.unsub_position(); ep.close()
> ```
> **cs 必须是 1**(以**上电**位姿为原点): 标定时抄的和运行中读的要是同一个原点。
> `cs=0` 是"以订阅那一刻的位置为原点", 拿它标定, 下次换个时刻订阅就整体错位。
> 这一点写进了 `config_ep.json` 的 `chassis.odom_cs`, driver 按它订阅。

操作:
1. **A**: 把**目标物(真机实际用矿泉水瓶, 见下方"目标物口径")**放到 A 标记 → 用 app/遥控把 EP
   开到"爪中轴对准目标物中心、爪底略高于它顶面"的位姿 → 读 odom → 填 `chassis.A_pose`。
2. **B**: 空车开到 B 标记同样的"对准、悬停"位姿 → 读 odom → 填 `chassis.B_pose`。
3. **HOME**: 挑一个离 A/B 都安全、不碍事的角落 → 读 odom → 填 `chassis.HOME_pose`。
   (每周期结束回 HOME, 把误差"重零"一部分, 同时方便你人工放块。)
4. 上面 A/B/HOME 三组数必须在**同一次开机**里读完才是一套 —— 中途重启过就重读(上电原点变了),
   并在 `calibration.note` 里写清是"哪次开机的原点"; 验收当天换场/重启同样重标。

> 若 A/B 转了朝向(不只是平移), 把 `z`(deg) 一起记下; 纯平移两处 `z` 通常一致。

## 2. 臂坐标 grab_low / lift_high(单位 mm, x前/y上)—— 一次标好

`ep_cycle.py` 只认两个绝对位姿: **lift_high**(悬停, 爪底高于目标物顶面) 与 **grab_low**(下探,
爪指到目标物的夹持高度)。A、B 同高时释放也复用 grab_low; 不同高就填 `release_low_override`。
**这两档是按目标物的形状/高度定的 —— 换成瓶子就必须重标, 不能沿用方块时代的旧值。**

标法(迭代):
1. 先在 config 里填两档猜测值(lift_high 高些、grab_low 低些; 同一 x 或按需要微调)。
2. 跑 `python3 ep/drive/env_check.py --config ep/config_ep.json --jog`:
   它会先移到 lift_high 再移到 grab_low, 每步**打印臂读回的 x/y**, 你人在旁边看爪实际到哪。
3. 对不上就改 config 再跑, 直到: lift_high 时爪底**高于目标物顶面**(移车/放物都刮不到),
   grab_low 时爪指**正好包住目标物的夹持部位**(能闭爪夹住)。夹的是竖放/横放的瓶子时,
   抓握高度与轴心都和方块差很多, 以"人眼看着夹稳"为准, 别照抄方块的值。

   > **读回值已经等推送追上再打印**(`rm.py` 的 `_settle_arm`)：SDK 的 `action_succeeded`
   > 比位置推送早约 0.5s（实测：指令 47ms 就报完成，但位置推送到 0.56s 后才出现新值），
   > 早先那样"紧跟动作完成就读"会把**动作前的旧位姿**打印出来。现在打印的是稳定后的位姿。
   > 位置读数走**订阅**(`_PushCache`)：SDK 没有 `arm.get_position()`, 只有 `sub_position`;
   > 判"连续两次一致"时只认**新推送样本**（5Hz 一帧 200ms），否则同一个样本会被读两次。
   > 若看到 `WARN: arm 读数 6s 内未稳定(行程被钳制? 推送断了?)`，说明这档 pose 可能超出臂行程、
   > 真机上根本没走到 —— 那次的读回**不能**填进 config，要改小再试。
   > 若看到 `WARN: arm 未到位 —— 要求 (…), 读回 … (差 …mm)`，同理：命令被钳制了，读数虽稳但
   > 不是你要的位置，**别**照它填。
   > 离线复现这三个场景：`python3 ep/tools/test_arm_settle_offline.py`（假 SDK 按实测时序建模）。
   > 另有一条不连机器人的接口核对：`python3 ep/tools/test_sdk_api_offline.py` —— 它拿仓库自带的
   > robomaster 副本逐个核对 driver 调用的接口是否真存在（`get_position` 那类错就是它拦的）。
4. 记下读回的 x/y —— 若与实际目标差一个固定偏移, 说明 SDK 该版本坐标原点不同, 以实测为准填。
   容差按 **±2mm** 看：实测稳态有 ±1mm 抖动，x 还有 +1mm 的固定偏移（74→75）。

> 爪的运动学/符号: **y 增大 = 向上**（已由 2026-09-13 的 5mm 实测坐实：指令 +5mm → 读回
> 74,57 → 75,62，人眼确认臂向上；证据见 `docs/真机侧证据_EP_20260913/`）。所以 lift_high 的
> y 要比 grab_low 大。臂垂直行程只 ~0.15m, **目标物要放在爪能下探够到的高度**:
2026-09-14 演示视频里 EP 在地面上夹放**矿泉水瓶**成功（瓶子有高度, 抓握面高）;
但若换回 5cm 方块, 块顶只 5cm, 放地面臂大概率够不到 —— 那种情况要垫高/放桌面。

## 3. 夹爪 open/close power(1..100)

- 先 60。`close` 后看能否**夹稳目标物且提起来不掉**: 掉 → 升 power; 夹得咯吱响/憋电机 →
  降。夹爪带力度控制, 不用拉满。**瓶身是圆的、比方块滑, 更容易转/滑脱** —— 60 这个起点是
  按方块给的, 瓶子要现场试; 掉了就往上加, 加到"带着走一段不转不掉"为止。
- 关键验证(**运送不松爪**): 1 周期跑时盯"闭爪后从 A 开到 B 的路上有没有松"。松就加
  close_power, 或检查 SDK 版本对 close 后是否自动维持。

## 4. 首跑纪律(和 c4_2 真机同一套)

0. **先解锁闸门**: §1–§3 标完后, 把 `config_ep.json` 的 `calibration` 改成
   `{"status": "calibrated", "by": "你的名字", "date": "2026-09-14", "venue": "场地"}`,
   并确认 `chassis` 的 HOME/A/B 已从 `null` 换成读到的 odom 三元组。
   跑 `python3 ep/core/selfcheck.py --config ep/config_ep.json`, 应看到
   `标定状态: calibrated (...)` 而不是 `⚠ 未标定`。没解锁就被 `ep_cycle` 拒绝是**正常设计**, 不是 bug。
1. `config_ep.json`: `cycle.pause_each_phase` 保持 `true`, `cycle.cycles=1`。
2. `bash ep/run_ep.sh ep/config_ep.json 1` —— 每段回车, HELD/PLACED 两处人工 y/n, 全程人盯。
3. 确认一个完整周期 OK 再 `bash ep/run_ep.sh ep/config_ep.json 5` 记 C5 结果。
4. 结果在 `ep_logs/run_*/result.json`, 回填验收记录表时与 c4_2 字段同列。
5. 连不上 EP 时会打印三条排查提示(SDK / 热点 / 工程形态), 不会甩 traceback;
   此时 `ep_logs/run_*/result.json` 会留下 `total: 0` 的记录 —— 那是"连都没连上", 不是"跑了失败"。

## 5. 掉点排查速查

| 现象 | 优先检查 |
|---|---|
| 到 A/B 每次偏 | 重新标底盘坐标; goto 后读 odom 看补正量 |
| 爪对不准目标物 | lift_high/grab_low 的 x 或 A_pose 的朝向 z |
| 夹不稳/运送掉 | close_power 太低或夹爪未 hold; 放置面不平 |
| 放下偏/翻 | B_pose 未标准; 放太低爪刮到目标物(释放前先抬一点)。瓶子会被**碰倒/滚走**, 比方块更明显 |
| arm 不动/报错 | 属性名被 env_check 探测到没? 非工程形态? SDK 版本 |
